# Runbook — エラーバジェット管理

最終更新: 2026-04-25

---

## エラーバジェットとは

SLOが「99.9%の可用性」の場合、残り0.1%が**エラーバジェット**（許容できる障害・ダウンタイムの枠）。

```
エラーバジェット = 100% − SLO目標値
月次許容ダウンタイム = 30日 × 24h × 60min × (1 − SLO)
```

| SLO | 月次許容ダウンタイム |
|:---|:---|
| 99.9% | 43.2分 |
| 99.5% | 216分（3.6時間） |
| 99.0% | 432分（7.2時間） |

---

## バジェット確認フロー

### 1. 現在のバジェット残量を確認

CloudWatch コンソール → メトリクス → 対象サービスの5xxエラーレートを確認

```
バジェット残量 = エラーバジェット総量 − 当月消費量
消費量 = 当月の総ダウンタイム（分）
```

### 2. バジェット消費率に応じた対応

| 消費率 | 状態 | 対応 |
|:---|:---|:---|
| 0〜50% | 正常 | 通常運用継続 |
| 50〜75% | 注意 | 変更凍結を検討・原因調査 |
| 75〜100% | 警戒 | 変更凍結・インシデント対応優先 |
| 100%超 | バジェット枯渇 | 変更凍結・SLO見直し検討 |

---

## バジェット枯渇時の対応手順

1. **変更凍結**: 新機能デプロイ・設定変更を停止
2. **原因特定**: CloudWatch Logs / X-Ray でエラー発生箇所を特定
3. **修正対応**: 障害原因を修正・デプロイ
4. **事後レビュー**: ポストモーテムを `docs/postmortems/` に記録（テンプレート: Issue #46）
5. **SLO見直し**: 枯渇が頻発する場合はSLO目標値の調整を検討
